# AWS DataSync Agent Setup Guide

## Overview
This guide covers the deployment and configuration of AWS DataSync agents for automated file transfer from on-premises or local systems to the AutoCorp S3 data lake. DataSync is used to transfer large CSV files generated by the sales order system.

## When to Use DataSync vs S3 CLI

### Use DataSync For:
- **Production environments** with scheduled, recurring file transfers
- Large files (>100GB) requiring optimized transfer
- Automated data validation and integrity checking
- Network bandwidth optimization and throttling
- Transfer from NFS, SMB, or HDFS file systems
- Compliance requirements for transfer logging

### Use S3 CLI For:
- **Development environments** with ad-hoc uploads
- One-time data migrations
- Files already on EC2 instances with IAM roles
- Simple, manual testing workflows

## Architecture Decision (AutoCorp Project)

**Development Environment:** Using S3 CLI for direct uploads (implemented)
**Production Recommendation:** DataSync with agent for automated, scheduled transfers

## DataSync Agent Deployment Options

### Option 1: VMware ESXi / vSphere (On-Premises)
Best for enterprise environments with existing VMware infrastructure.

**Requirements:**
- VMware ESXi 6.5 or later
- 4 vCPUs, 32 GB RAM minimum
- 80 GB disk space
- Network connectivity to AWS (HTTPS 443, NTP 123)

**Deployment Steps:**
1. Download DataSync agent OVA from AWS Console
2. Deploy OVA to ESXi host
3. Power on VM and access activation URL
4. Activate agent with AWS credentials

### Option 2: Amazon EC2 (Cloud-Based Testing)
Best for testing DataSync in AWS environment without on-premises infrastructure.

**Advantages:**
- No hypervisor required
- Fast deployment for testing
- Uses AWS networking (no VPN required)
- Cost-effective for development

**EC2 Instance Requirements:**
- Instance type: m5.xlarge or larger
- AMI: AWS DataSync Agent AMI (available in marketplace)
- EBS volume: 80 GB gp3
- Security group: Allow inbound 80/443 (for activation)
- IAM instance profile with S3 access

**Deployment Steps:**
```bash
# Launch EC2 instance with DataSync AMI
aws ec2 run-instances \
  --image-id ami-0abcdef1234567890 \
  --instance-type m5.xlarge \
  --key-name autocorp-keypair \
  --security-group-ids sg-xxxxxxxxx \
  --subnet-id subnet-xxxxxxxxx \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=autocorp-datasync-agent}]'

# Get instance public IP
AGENT_IP=$(aws ec2 describe-instances --instance-ids i-xxxxxxxxx --query 'Reservations[0].Instances[0].PublicIpAddress' --output text)

# Access activation URL
echo "Activation URL: http://${AGENT_IP}"
```

### Option 3: Hyper-V (Windows Server)
Best for Windows-centric environments.

**Requirements:**
- Windows Server 2012 R2 or later with Hyper-V
- 4 vCPUs, 32 GB RAM
- 80 GB VHDX disk

**Deployment Steps:**
1. Download DataSync agent VHD from AWS Console
2. Import VHD into Hyper-V
3. Configure virtual switch with external network
4. Start VM and activate via web interface

## Agent Activation Process

### Prerequisites
- AWS account with permissions to create DataSync resources
- Network route from agent to AWS (VPC endpoint or internet gateway)
- Agent accessible via HTTP port 80 (for initial activation only)

### Activation Steps

1. **Access Activation URL:**
   ```
   http://<AGENT_IP_ADDRESS>
   ```

2. **Select AWS Region:**
   Choose the same region as your S3 bucket (us-east-1 for AutoCorp)

3. **Provide AWS Credentials:**
   - Option A: Use AWS Console (recommended)
   - Option B: Use AWS CLI with access keys

4. **Get Activation Key:**
   ```bash
   aws datasync create-agent \
     --agent-name autocorp-datasync-agent-dev \
     --activation-key <KEY_FROM_AGENT_UI> \
     --region us-east-1
   ```

5. **Save Agent ARN:**
   Store the returned agent ARN for Terraform configuration:
   ```
   arn:aws:datasync:us-east-1:696056865313:agent/agent-xxxxxxxxxxxxxxxxx
   ```

## Network Configuration

### Firewall Rules
Agent must reach these AWS endpoints:

**Outbound from Agent:**
- **HTTPS (443):** *.datasync.us-east-1.amazonaws.com
- **HTTPS (443):** *.s3.us-east-1.amazonaws.com
- **NTP (123):** time.aws.com (for time synchronization)

**Inbound to Agent (Activation Only):**
- **HTTP (80):** From your workstation (temporary, can be disabled after activation)

### VPC Endpoint Option (Production)
For private connectivity without internet gateway:

```bash
# Create VPC endpoint for DataSync
aws ec2 create-vpc-endpoint \
  --vpc-id vpc-xxxxxxxxx \
  --service-name com.amazonaws.us-east-1.datasync \
  --route-table-ids rtb-xxxxxxxxx \
  --subnet-ids subnet-xxxxxxxxx

# Create VPC endpoint for S3
aws ec2 create-vpc-endpoint \
  --vpc-id vpc-xxxxxxxxx \
  --service-name com.amazonaws.us-east-1.s3 \
  --route-table-ids rtb-xxxxxxxxx
```

## Terraform Integration

### 1. Update terraform.tfvars
After agent activation, add agent ARN:

```hcl
enable_datasync = true
datasync_agent_arns = ["arn:aws:datasync:us-east-1:696056865313:agent/agent-xxxxxxxxxxxxxxxxx"]
datasync_schedule = "rate(1 hour)"  # Adjust as needed
```

### 2. Review DataSync Module
The module is already implemented at `terraform/modules/datasync/main.tf`:

```bash
cd terraform
terraform plan -target=module.datasync
```

### 3. Deploy DataSync Resources
```bash
terraform apply -target=module.datasync
```

This creates:
- Source location (NFS/SMB mount point)
- Destination location (S3 bucket)
- DataSync task with schedule
- CloudWatch log group for monitoring

## DataSync Task Configuration

### Source Location Setup

**For NFS Share:**
```bash
# Mount point on DataSync agent
/data/autocorp/csv/
```

**For SMB Share (Windows):**
```bash
# UNC path
\\fileserver\autocorp\csv
```

**Required Credentials:**
- NFS: No authentication (exports file)
- SMB: Domain user with read permissions

### Destination Location (S3)
```
s3://autocorp-datalake-dev/raw/csv/
```

**Options:**
- Storage class: STANDARD
- Verification mode: POINT_IN_TIME_CONSISTENT
- Overwrite mode: ALWAYS

## Task Scheduling

### Schedule Options

**Hourly Transfer:**
```hcl
schedule_expression = "rate(1 hour)"
```

**Daily at 2 AM:**
```hcl
schedule_expression = "cron(0 2 * * ? *)"
```

**Business Hours Only (M-F, 8 AM - 6 PM):**
```hcl
schedule_expression = "cron(0 8-18 ? * MON-FRI *)"
```

### Manual Execution
```bash
# Start task immediately
aws datasync start-task-execution \
  --task-arn arn:aws:datasync:us-east-1:696056865313:task/task-xxxxxxxxxxxxxxxxx
```

## Monitoring and Troubleshooting

### CloudWatch Metrics
Key metrics to monitor:
- BytesTransferred
- FilesTransferred
- VerificationErrorCount
- TaskExecutionDuration

### CloudWatch Logs
Log group: `/aws/datasync/task-xxxxxxxxxxxxxxxxx`

**Common Log Patterns:**
```bash
# View recent logs
aws logs tail /aws/datasync/task-xxxxxxxxxxxxxxxxx --follow

# Search for errors
aws logs filter-log-events \
  --log-group-name /aws/datasync/task-xxxxxxxxxxxxxxxxx \
  --filter-pattern "ERROR"
```

### Troubleshooting Common Issues

#### Issue: Agent Not Activating
**Symptoms:** Cannot access http://<AGENT_IP>
**Solutions:**
- Verify VM is running and network is configured
- Check security group allows inbound port 80
- Ensure DNS resolution works from agent
- Try accessing from same subnet/network

#### Issue: Task Fails with "Access Denied"
**Symptoms:** Task execution fails immediately
**Solutions:**
- Verify IAM role has s3:PutObject permissions
- Check S3 bucket policy allows DataSync service principal
- Ensure agent has network path to S3 endpoints
- Verify source file permissions

#### Issue: Slow Transfer Speed
**Symptoms:** Transfer takes longer than expected
**Solutions:**
- Check network bandwidth between agent and AWS
- Increase agent instance size (more vCPUs)
- Enable parallel transfers (default: 8, max: 16)
- Use VPC endpoint for lower latency

#### Issue: Files Not Transferred
**Symptoms:** Some files missing in S3
**Solutions:**
- Check file permissions on source
- Verify filters in task configuration
- Review CloudWatch logs for specific errors
- Ensure files aren't locked/in-use during transfer

## Cost Optimization

### DataSync Pricing (us-east-1)
- Data scanned: $0.0125 per GB
- Data transferred to AWS: No charge (inbound is free)
- Data validation: Included

### Example Cost Calculation (AutoCorp)
```
Daily CSV uploads: 431 MB (0.43 GB)
Monthly data: 0.43 GB × 30 = 12.9 GB
Cost: 12.9 GB × $0.0125 = $0.16/month
```

**Note:** For dev environment, S3 CLI is more cost-effective ($0/month vs $0.16/month). DataSync recommended for production with automation requirements.

### Cost Reduction Tips
1. Use schedule to transfer only during off-hours
2. Enable deduplication filters to skip unchanged files
3. Use lifecycle policies to transition old raw data to Glacier
4. Consider Direct Connect for very large transfers (>1 TB/day)

## Security Best Practices

### Access Control
1. **Agent IAM Role:** Minimal permissions (S3 write only)
2. **S3 Bucket Policy:** Restrict to DataSync service principal
3. **Encryption:** Enable S3 SSE-KMS for data at rest
4. **TLS:** All data in transit uses TLS 1.2+

### Example S3 Bucket Policy
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowDataSyncAccess",
      "Effect": "Allow",
      "Principal": {
        "Service": "datasync.amazonaws.com"
      },
      "Action": [
        "s3:PutObject",
        "s3:GetObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::autocorp-datalake-dev/raw/csv/*",
        "arn:aws:s3:::autocorp-datalake-dev"
      ]
    }
  ]
}
```

### Network Isolation
- Deploy agent in private subnet with NAT gateway
- Use VPC endpoints for AWS service access
- Enable VPC Flow Logs for audit trail
